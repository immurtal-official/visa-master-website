# Visa Master MVP 范围：V1 成都→西班牙申根旅游签，V2 中国境内→美国 B1/B2

## 1. MVP 总原则

Visa Master 的 MVP 不应该追求“覆盖所有国家所有签证”，而应该证明一个更关键的假设：

> 对一个具体签证路线，系统是否能稳定地把用户 intake 信息转化为官方来源可追溯、材料互相一致、经过机器检查和人工复核的可提交材料包。

因此，V1 要极窄，但要完整。

---

## 2. V1 范围：成都 → 西班牙申根旅游签证

### 2.1 V1 目标

证明以下能力：

1. 用户能在线完成结构化 intake。
2. 系统能基于成都领区和西班牙申根旅游签证生成材料清单。
3. 系统能生成一个完整材料包。
4. 材料包内的信息前后一致。
5. 人工审核可以在可控时间内完成。
6. 用户愿意为这个结果付费。

---

### 2.2 V1 支持对象

| 维度 | V1 范围 |
|---|---|
| 申请人国籍 | 中国公民 |
| 当前地点 | 成都领区相关用户 |
| 目的地 | 西班牙 |
| 签证类型 | 申根旅游签证 |
| 出行类型 | 个人旅游为主 |
| 用户类型 | 本人申请或简单代他人申请 |
| 交付形式 | zip/folder 材料包 |
| 审核方式 | 每单人工复核 |

---

### 2.3 V1 用户端功能

#### 必须有

1. **路线选择**
   - 申请人国籍
   - 当前居住城市/领区
   - 目的国家
   - 签证类型
   - 出行时间

2. **账号与申请草稿**
   - 创建申请
   - 保存进度
   - 回来继续填写

3. **Intake form**
   - 个人基本信息
   - 护照信息
   - 工作/收入信息
   - 储蓄/财务信息
   - 旅行计划
   - 同行人/资助情况
   - 历史签证或拒签情况

4. **材料上传**
   - 护照
   - 银行流水或资产证明
   - 在职/收入相关信息
   - 其他根据路线需要的材料

5. **支付与提交**
   - 单次材料包付费
   - 明确服务范围
   - 明确不承诺过签

6. **进度页**
   - 已提交
   - 官方来源核对中
   - 材料生成中
   - 一致性检查中
   - 人工复核中
   - 需要补充信息
   - 可下载

7. **补材料流程**
   - 结构化补材料请求
   - 用户上传或修改
   - 重新提交

8. **交付下载**
   - 下载材料包
   - 文件目录说明
   - Read-first checklist
   - 官方来源和 caveats

---

### 2.4 V1 后台功能

#### 必须有

1. **申请列表**
   - 状态筛选
   - 路线筛选
   - 待审核队列

2. **申请详情**
   - 用户 intake 数据
   - 上传材料
   - AI/Agent 输出
   - QA 报告
   - 来源列表

3. **人工审核 checklist**
   - 材料是否完整
   - 关键字段是否一致
   - 来源是否当前有效
   - 是否需要补材料
   - 是否可交付

4. **补材料请求**
   - 创建请求
   - 指定字段/文件
   - 写明原因
   - 用户端可见

5. **交付控制**
   - 人工确认后才允许交付
   - 生成下载链接
   - 记录交付时间

### 2.5 V1 交付内容

材料包建议结构：

```text
00_Start_Here/
  Read-first master checklist
  Submission index

01_Official_Documents/
  官方 checklist
  申请表 PDF 或说明
  相关 acknowledgement/questionnaire

02_Editable_Templates/
  Application form field guide
  Employment & leave certificate
  Day-by-day itinerary
  Cover letter
  Optional financial explanation

04_Sources_and_Warnings/
  Sources cited
  Current caveats
  Human review notes
```

### 2.6 V1 明确不做

| 不做 | 原因 |
|---|---|
| 不承诺签证通过 | 签证结果由领馆决定 |
| 不自动替用户提交 | 涉及预约、签字、现场材料、本人到场等复杂事项 |
| 不覆盖所有申根国家 | 每个目的国和领区规则不同，先验证一个路线 |
| 不做复杂家庭多人申请 | 会显著增加数据结构和审核复杂度 |
| 不做完全自动交付 | 人工审核是信任机制和风险控制 |
| 不做开放式 AI 聊天顾问 | 容易产生幻觉和责任边界问题 |
| 不处理复杂拒签史/高风险背景 | 需要专业顾问或律师判断 |

---

### 2.7 V1 成功指标

#### 产品指标

- 用户完成 intake 的比例。
- 用户从开始到提交的时间。
- 补材料率。
- 材料包一次通过人工审核的比例。
- 人工审核平均耗时。
- 用户是否成功下载并使用材料包。

#### 商业指标

- 访问首页到开始申请转化率。
- 开始申请到付款转化率。
- 单 pack 毛利。
- 每单人工审核时间。
- 用户愿意支付的价格区间。

#### 质量指标

- 材料一致性错误数量。
- 官方来源过期或错误数量。
- 文档渲染问题数量。
- 用户投诉和退款原因。

## 3. V2 范围：中国境内 → 美国 B1/B2 签证

### 3.1 V2 目标

V2 不是简单增加一个国家，而是验证 Visa Master 能否从“申根纸质材料包逻辑”扩展到“美国 B1/B2 在线申请与面签准备逻辑”。

美国 B1/B2 与申根旅游签不同：

- 更强调 DS-160 在线表格。
- 更强调面签和个人陈述一致性。
- 材料未必像申根那样固定提交，但支持性材料和回答逻辑仍然重要。
- 用户焦虑更集中在“怎么填 DS-160、面签怎么解释、是否容易被拒”。

---

### 3.2 V2 支持对象

| 维度 | V2 范围 |
|---|---|
| 申请人国籍 | 中国公民 |
| 当前地点 | 中国境内某城市，具体先选一个或少数城市 |
| 目的地 | 美国 |
| 签证类型 | B1/B2 旅游/商务访问签证 |
| 出行类型 | 旅游、探亲、短期商务、会议 |
| 交付形式 | DS-160 填写指导 + 面签准备包 + 支持材料 checklist |
| 审核方式 | 人工复核关键字段和风险点 |

---

### 3.3 V2 产品差异

| 方面 | V1 西班牙申根旅游签 | V2 美国 B1/B2 |
|---|---|---|
| 核心材料 | 申请表、行程、在职证明、银行流水、cover letter | DS-160 信息整理、面签准备、支持材料 checklist |
| 主要风险 | 材料缺失、字段不一致、领区/表格错误 | DS-160 填写错误、面签回答不一致、移民倾向解释不足 |
| 用户焦虑 | “材料够不够、格式对不对” | “面签会问什么、怎么回答、DS-160 怎么填” |
| 系统价值 | 自动生成材料包 | 结构化整理信息、生成 DS-160 填写 guide、面签准备 |
| 交付形式 | 文件包 | 指导包 + checklist + 面签问答准备 |

---

### 3.4 V2 用户端功能新增

1. **DS-160 信息采集结构**
   - 个人信息
   - 护照信息
   - 美国旅行计划
   - 联系人/邀请人
   - 工作/教育经历
   - 家庭信息
   - 过往赴美/签证记录
   - 安全问题相关说明

2. **面签准备模块**
   - 常见问题
   - 根据用户背景生成可能问题
   - 回答要点，不生成虚假故事
   - 强调真实、一致、简洁

3. **支持材料 checklist**
   - 工作证明
   - 收入/资产证明
   - 行程计划
   - 邀请函，如适用
   - 家庭/工作/资产约束证明，如适用

4. **风险提示**
   - 拒签史
   - 无稳定工作
   - 出行目的模糊
   - 资金来源不清
   - 回国约束较弱

---

### 3.5 V2 明确不做

| 不做 | 原因 |
|---|---|
| 不替用户编造面签答案 | 高风险且不合规 |
| 不承诺通过 | B1/B2 高度依赖面签和领事判断 |
| 不自动提交 DS-160 | 用户需要确认和签署真实信息 |
| 不处理复杂移民倾向问题 | 可能需要专业法律建议 |
| 不替代律师 | 产品应定位为材料准备和一致性辅助 |

## 4. V1 到 V2 的扩展判断

### 4.1 什么时候可以做 V2？

建议满足以下条件再进入 V2：

1. V1 至少完成 20–50 个真实或 beta 用户 pack。
2. V1 人工审核平均耗时可控。
3. V1 用户愿意为交付结果付费。
4. V1 材料一致性错误率明显下降。
5. V1 的 intake、上传、支付、审核、交付流程已经稳定。

### 4.2 V2 的核心风险

- 美国 B1/B2 更接近“面签叙事一致性”问题，不只是材料格式问题。
- 用户可能期待“帮我提高过签率”，需要强边界说明。
- DS-160 相关内容必须特别谨慎，不能替用户虚构。

## 5. 产品路线建议

```text
Phase 0: 内部 demo
- 成都 → 西班牙申根旅游签
- 手动邀请 beta 用户
- Founder 人工审核所有 pack

Phase 1: V1 paid beta
- 公开支持一个路线
- 单次收费
- 基础 dashboard
- 人工审核强制

Phase 2: V1 route expansion
- 其他申根目的国
- 其他中国领区
- 路线缓存和模板复用

Phase 3: V2 美国 B1/B2
- 一个或少数中国城市开始
- DS-160 guide + 面签准备包
- 更强免责声明和风险提示

Phase 4: 多路线平台
- 支持更多目的国
- 申请人档案复用
- 家庭成员管理
- 审核者工作台强化
```

## 6. MVP 的关键战略选择

最重要的选择是：

> 不要先做“签证百科网站”，先做“一个路线可真实交付的材料包产品”。

原因：

1. 百科内容容易被免费攻略替代。
2. 用户真正愿意付费的是材料准备、检查和交付。
3. 每个路线的官方来源、表格和领区规则都不同，必须用路线作为基本单位积累。
4. 先做窄路线可以控制质量和人工审核成本。
5. 一旦一个路线跑通，后续扩展才有工程和运营复用价值。
