# Visa Master 用户画像总结

## 1. 产品定位前提

Visa Master 的核心产品不是“帮用户搜索签证攻略”，而是把用户的签证申请需求转化为一个可提交、内部一致、经过机器检查和人工复核的材料包。

典型任务：

> 用户说：“我住在成都，想申请西班牙旅游签。”
> 系统输出：官方来源、申请表说明、材料清单、行程、在职/准假证明模板、cover letter、财务说明、提交索引和警示说明。

当前 V1 beachhead：

> 中国公民，在中国境内，从成都领区申请西班牙申根旅游签证。

未来 V2 方向：

> 中国公民，在中国境内某个城市申请美国 B1/B2 旅游/商务签证。

## 2. 核心用户画像

### Persona A：自助型年轻/中青年申请人

**年龄段**：20–40 岁

**典型身份**：

- 白领、互联网/科技/金融/教育/医疗等行业从业者
- 学生、研究生、刚工作几年的人
- 有出境旅游、探亲、短期商务、会议参会需求的人

**能力特征**：

- 会用电脑和手机。
- 可以独立填写在线表格。
- 愿意自己上传材料、核对信息。
- 不一定懂签证规则，但愿意跟着系统一步一步做。

**核心需求**：

- 不想花很多时间查官方要求。
- 不想在小红书、知乎、旅行社攻略和官网之间反复比对。
- 想知道自己到底该交什么材料。
- 想减少表格、行程、在职证明、银行流水说明之间的信息不一致。

**付费理由**：

- 几百元可以省掉大量时间。
- 比旅行社便宜。
- 比自己照着网上攻略做更稳。
- 交付的是完整材料包，而不是一篇泛泛攻略。

**主要顾虑**：

- AI 会不会乱编？
- 我的护照和银行流水安全吗？
- 出错了谁负责？
- 系统生成的材料真的能用吗？

---

### Persona B：中产/准中产的高确定性用户

**年龄段**：30–55 岁

**典型身份**：

- 已工作多年，有稳定收入和家庭安排的人。
- 准备家庭旅行、夫妻旅行、商务短停、探亲访友。
- 可能已经被旅行社报价劝退。

**能力特征**：

- 可以使用电脑和微信/支付宝。
- 不一定喜欢折腾复杂网站。
- 希望流程像“报税软件”或“在线保险申请”一样清楚。

**核心需求**：

- 知道每一步为什么要填。
- 知道材料缺什么。
- 知道自己的信息是否前后一致。
- 知道签证中心、领区、表格、费用、预约入口等信息来自哪里。

**付费理由**：

- 他们不是完全没有钱，而是不想为普通旅游签证付旅行社高价。
- 相比纯 DIY，愿意为“省心、可靠、可解释”付费。
- 价格如果在 ¥199–399 之间，心理上更像“专业辅助工具”，不是高价代理。

**主要顾虑**：

- 会不会最后还是要我自己做很多？
- 会不会生成的东西不符合领馆要求？
- 会不会把我的个人信息泄露？
- 是否有人工帮我看？

---

### Persona C：代办型家庭成员

**年龄段**：25–45 岁为主

**典型身份**：

- 子女帮父母办理旅游签证。
- 配偶帮另一方填写资料。
- 成年子女帮家庭成员整理材料。

**实际申请人**：

- 可能是父母、配偶、孩子或亲属。
- 真实申请人未必熟悉电脑。

**能力特征**：

- 操作者熟悉电脑和手机。
- 但材料来自另一个人，可能需要反复询问。
- 需要多人信息管理、保存草稿、补充材料、检查关系说明。

**核心需求**：

- 支持“我帮别人办”。
- 支持多个申请人。
- 支持分步保存，不要求一次填完。
- 对材料用途解释清楚，方便操作者向父母/亲属索要材料。

**付费理由**：

- 家庭成员自己办很耗时间。
- 找旅行社又贵又不透明。
- 系统化收集信息可以减少来回沟通。

**主要顾虑**：

- 父母材料不齐怎么办？
- 银行流水、退休证明、房产/存款等材料如何处理？
- 不同家庭成员的信息能不能分开管理？

## 3. 非核心用户

### 暂时不优先服务的人群

| 用户类型 | 暂不优先原因 |
|---|---|
| 完全不会使用手机/电脑的老年申请人 | 需要线下服务、电话服务或人工代办，不适合 V1 自助流程 |
| 极低预算用户 | 可能更倾向免费攻略或模板，不愿付费 |
| 高净值复杂签证用户 | 可能需要律师、移民顾问或高端旅行社，不适合 V1 标准化材料包 |
| 高风险拒签背景用户 | 涉及复杂解释、拒签史、敏感职业、资产证明困难，V1 不应承诺解决 |
| 企业批量差旅用户 | 可能是后续 B2B 机会，但不是 V1 的最小验证目标 |

## 4. 用户真正购买的价值

用户表面上买的是“签证材料包”，实际购买的是：

1. **确定性**：知道自己属于哪个领区、该交什么材料、去哪里提交。
2. **一致性**：表格、行程、证明、说明信中的日期、城市、单位、收入等信息一致。
3. **省时间**：减少搜索、比对、复制粘贴和反复修改。
4. **可解释性**：每个要求能追溯到官方来源，而不是来自模糊攻略。
5. **心理安全感**：知道有人工复核，而不是完全交给 AI。
6. **性价比**：比旅行社便宜，比免费攻略可靠。

## 5. 用户核心焦虑

| 焦虑 | 产品需要如何回应 |
|---|---|
| 怕拒签 | 不承诺过签，强调减少材料错误和不一致 |
| 怕 AI 编造 | 强调官方来源、来源引用、人工复核 |
| 怕隐私泄露 | 说明数据用途、保留时间、删除方式、访问权限 |
| 怕流程复杂 | 分步骤、保存草稿、清楚进度、少字段一屏 |
| 怕材料缺失 | 用 checklist、缺失提醒、补材料流程 |
| 怕花钱没效果 | 展示交付样例、价格、交付内容、退款/限制说明 |

## 6. 对产品设计的直接启示

### 6.1 网站视觉不能过度“AI 炫技”

签证是高信任事项，用户上传的是护照、银行流水、在职证明等敏感材料。视觉应该可靠、清晰、专业，而不是像娱乐型 AI demo 或 crypto 项目。

### 6.2 首页第一屏必须解释清楚“你到底交付什么”

用户第一眼应该看到：

- 我填写一次信息。
- 系统查询当前官方要求。
- 自动生成互相一致的材料包。
- 人工复核后交付。

### 6.3 Intake form 要像“报税软件”而不是普通网页表单

关键是：

- 一步一步问。
- 每一步解释为什么问。
- 可保存、可回来继续。
- 错误提示具体。
- 显示进度。

### 6.4 需要支持“为他人申请”

V1 即使不做复杂家庭账户，也应该在语言和数据结构上区分：

- 账号使用者
- 实际申请人
- 付款人
- 联系人

### 6.5 用户不一定买“AI”，用户买“更稳的材料准备流程”

AI 应该被表达为后台能力，而不是品牌主角。更好的表达是：

> 官方来源检索 + 材料自动生成 + 一致性校验 + 人工复核。
