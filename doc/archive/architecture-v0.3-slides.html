Secure Agent Architecture v0.3

The outbound & lifecycle half the v0.2 diagram was missing. The trust boundary stays; what's new is egress control, an async job path, and ephemeral single-tenant execution — because this agent browses the live web and runs code on the user's data.

Backend is the control plane. The agent is a disposable worker beyond the boundary, reached only via a queue, and it touches the internet only through an egress proxy.

Job lifecycle — ephemeral & single-tenant

One job at a time (MVP). A fresh writable space is created, used, pulled from, then destroyed with the container — no PII survives to the next user.

1
Fresh scratch
Empty volume/tmpfs; stage this user's uploads into it.
2
Launch
Read-only agent+runtime · fresh scratch · scoped key · --yolo.
3
Run & stream
research → retrieval → build → QA; progress → Backend.
4
Done by artifact
Watch qa-report.json, not process exit. Deadline backstop.
5
Pull & validate
Backend validates, stores to S3, routes to review.
6
Destroy
Remove container + delete scratch (rm -v). PII gone.
🟢 one concurrent job (MVP) — the same isolation generalizes to a per-tenant worker pool at scale.

03

Egress control — the boundary is the network

The container has no default route; its only path out is the proxy. Never trust the agent to self-limit. Kills exfiltration & SSRF under prompt injection.

🤖 Hermes container
internal:true net — no gateway; HTTP(S)_PROXY enforced
→
🛡️ Egress Proxy
Squid / Envoy · audit every request
→
🌍 Internet
only what policy allows
BLOCK
Internal + metadata + odd ports. RFC1918, 169.254.0.0/16 (cloud metadata → IAM theft), 127/8, anything not 80/443 — kills SSRF.
ALLOW
Inference channel. Only the LLM provider host(s); the model key goes nowhere else.
ALLOW
Research reads. Public web GET for embassy / BLS / gov pages & PDFs.
LIMIT
Constrain data-sends. Block/scrutinize POST/PUT + large bodies to non-allowlisted hosts — exfiltration has to send data out. Rate + bandwidth caps.
PHASE 2
Egress DLP. TLS-intercept & scan outbound for this job's PII (passport №, balance) → block on match.

Data-dir split — reuse the runtime, never the PII

Don't rebuild the ~1 min Python venv every job, yet never share writable state. Non-PII parts mount read-only; only PII-bearing parts are ephemeral.

🔒 Shared · read-only

no PII · baked or RO volume

  • profiles/visa-master-agent — SOUL + skills
  • local/toolchain-runtime — Python venv (docx, pypdf, reportlab)
  • auth.json — model service credential, not user data

♻️ Per-job · writable · ephemeral

holds PII · destroyed after

  • workbench/ — downloaded sources, manifests, renders
  • workspace/ — the generated delivery pack
  • sessions/ — conversation state
  • uploads/ — the user's documents
